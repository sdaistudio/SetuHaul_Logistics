SetuHaul database: ER diagram and data browser

Click any table in the diagram, or a link below it, to open its full data. Foreign-key values are links: click one to jump to the row it points at. Each table has its own link (e.g. #t-shipments) you can bookmark or share.

What the SQL file contains

Structure, in file order
1
Header comments (snapshot date, how to rebuild) and BEGIN TRANSACTION.
2
For each of the 18 tables: a CREATE TABLE with primary key, NOT NULL, CHECK rules (allowed codes, e.g. dock_type IN STANDARD/REEFER/HEAVY; end after start), UNIQUE rules and FOREIGN KEYs, followed straight away by that table's INSERT rows (the seed data).
3
Seven indexes, including the two partial unique indexes that stop double booking (one active booking per slot; one current booking per shipment).
4
Four views that answer common questions (latest ETA, slot availability, inbound state, yard queue).
5
COMMIT. Running the file on an empty SQLite database produces a database identical to the supplied .db (checked row by row).
Worth knowing
  • The file never runs PRAGMA foreign_keys = ON. SQLite leaves foreign-key checking off by default, so the 30 foreign keys are declared but only enforced if the application turns them on per connection (our prototype does). Today's data has no violations.
  • No triggers and no DROP statements: run it on an empty database, or it fails on the first existing table.
  • Timestamps are ISO-8601 text with +05:30; comparisons work only because every value uses the same format.
  • The CHECK rules protect codes and simple ranges, not cross-table rules: nothing stops an overweight truck being booked on a weak dock, or a booking inside a breakdown window.
