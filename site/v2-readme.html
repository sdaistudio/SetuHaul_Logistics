The engine decision

The review recommended a priority list plus repair as the planner, benchmarked against exhaustive search. We kept both, in two roles:

  • Engine of record: exact branch and bound over the order in which trucks get their earliest feasible door (planner.exact). It is warm-started by the priority + repair answer. A branch is cut when the trucks already placed, plus each remaining truck's best placement on the door time still free, cannot beat the best plan found. It stops at a node count (EXACT_NODE_LIMIT = 200,000), not a clock, so every run gives the same answer.
  • First answer: priority list + repair. The coordinator sees it at once, and planner.explain gives each truck a one-line reason ("ready 11:40; fits D2, D4; gets D2 12:20; waits 40 min because SHP1005, SHP1009 use those docks first").

On the 09:45 snapshot (8 trucks): proven optimal after 5,425 nodes, out of 40,320 possible orders. The exhaustive benchmark and priority + repair give the same plan: 1 truck with no door (the reefer, whose only door is in maintenance), priority-weighted wait 1,120, CRITICAL wait 40 min, longest HIGH/CRITICAL wait 65 min. The plan stays the same under all three weight sets tested.

One visible effect in the scenario replay: at 09:36, DRV013 (LOW) picks D4 12:40 in a race with DRV006. The exact plan had earmarked that slot for HIGH SHP1006, so the commit now refuses DRV013 with "reserved for a higher-priority load" (before: "just taken by another truck") and offers D1 at 14:00. Every other turn and every scenario measure is unchanged.
